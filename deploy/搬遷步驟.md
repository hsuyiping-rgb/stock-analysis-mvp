# 排程搬遷步驟（搬到不關機的 Windows 電腦）

> 目的：ETF 持股快照與三大法人快照兩個每日排程，從筆電（DESKTOP-31QBU95）搬到一台不關機的 Windows 電腦。
> 建立日期：2026-08-16

## 為什麼要搬

原本的筆電在排程時間（18:00／18:30）常處於睡眠狀態。2026-08-13、08-14 兩天就因此完全沒抓到資料：

- ETF：靠 `WakeToRun` 喚醒後補跑，但剛喚醒時網路未就緒、`fetch` 無逾時而無限等待，達 30 分鐘 `ExecutionTimeLimit` 被強制終止（`0xC000013A`），兩天分別只抓到 4 檔與 0 檔。
- 三大法人：當時 `StartWhenAvailable=False`，錯過排程時間就不補跑，直接被拒絕執行（`0x800710E0`）。

程式面已修（`etf_holdings.mjs` 加上 20 秒逾時與單檔重試），排程設定也已修正。但根本解法是換一台不睡眠的機器。

## 本資料夾的檔案

| 檔案 | 用途 |
|---|---|
| `ETF持股每日快照.xml` | 工作排程器匯出檔，週一至五 18:00 |
| `三大法人每日快照.xml` | 工作排程器匯出檔，週一至五 18:30 |

兩個 XML 都已是修正後的版本：`StartWhenAvailable=True`、`WakeToRun=True`、`ExecutionTimeLimit=PT30M`。

## 採用的方案

**專案仍放 Google Drive，路徑完全不變**：`G:\我的雲端硬碟\AI作品\投資股票分析`

這樣排程 XML 與 `.ps1` 都不用改，資料也會自動同步回其他電腦。

⚠️ **限制**：`G:` 是 Google Drive Desktop 掛給「已登入的互動工作階段」的虛擬磁碟。排程必須維持「**只有使用者登入時才執行**」，且新電腦要設定自動登入、永不睡眠、永不登出。若改成「不論使用者是否登入都執行」，`G:` 不存在，排程必定失敗。

這兩個管線純用 Node 內建 `fetch`，沒有任何 npm 依賴，不會踩到 Google Drive 鎖檔問題（見 `docs/chips-api.md`）。

## 執行步驟（在新電腦上做）

### 1. 安裝三樣東西

- **Node.js**：LTS 22 以上（程式用到 `AbortSignal.timeout`，需 Node 17.3+）
- **Git**
- **Google Drive Desktop**：登入同一帳號，**確認掛載成 `G:` 磁碟機**，且「我的雲端硬碟\AI作品\投資股票分析」已同步完成

### 2. 確認 `config.local.json`

路徑：`G:\我的雲端硬碟\AI作品\投資股票分析\config.local.json`

包含四個鍵：`FINMIND_TOKEN`、`GMAIL_ADDRESS`、`GMAIL_APP_PASSWORD`、`ETF_MAIL_TO`。

此檔在 `.gitignore` 內、不進版控，但**在 Google Drive 上**，所以同步下來就有。若沒有，請用隨身碟或加密方式自行複製，**不要走聊天軟體或郵件傳送**。

### 3. 電源設定：永不睡眠

```powershell
powercfg /change standby-timeout-ac 0
powercfg /change hibernate-timeout-ac 0
```

再到「設定 → 系統 → 電源」確認沒有自動休眠。用 `netplwiz` 設定**自動登入**，停電重開後 `G:` 才會自己回來。

### 4. 確認時區

新電腦時區必須是**台北**。否則 `etf_holdings.mjs` 的 `rocDateCandidates()` 算出的公告日會偏一天。

### 5. 先手動跑一次（別直接信排程）

```powershell
cd "G:\我的雲端硬碟\AI作品\投資股票分析"
node .\etf_holdings.mjs
node .\institutional_flows.mjs
```

驗收標準：
- ETF 14 檔都有輸出（`00983A`、`00990A` 持股為美股、資料 T+1，日期比其他檔舊一天屬正常）
- `reports\etf-analysis-latest.html` 有產生
- 信箱有收到報告信

有問題先解決再往下做。

### 6. 匯入兩個排程

把 `新使用者名稱` 換成新電腦的 Windows 帳號：

```powershell
cd "G:\我的雲端硬碟\AI作品\投資股票分析\deploy"
Register-ScheduledTask -Xml (Get-Content "ETF持股每日快照.xml" -Raw) -TaskName "ETF持股每日快照" -User "新使用者名稱"
Register-ScheduledTask -Xml (Get-Content "三大法人每日快照.xml" -Raw) -TaskName "三大法人每日快照" -User "新使用者名稱"
```

XML 裡的 `UserId` 是舊機的 `vm`，**一定要用 `-User` 覆蓋**。

匯入後在工作排程器對兩個工作各按一次「執行」，確認 `LastTaskResult` 是 `0x0`。

### 7. 停用舊筆電的排程

**等新機連續跑穩兩、三天再做。** 在舊筆電（DESKTOP-31QBU95）上執行：

```powershell
Disable-ScheduledTask -TaskName "ETF持股每日快照"
Disable-ScheduledTask -TaskName "三大法人每日快照"
```

停用而非刪除，新機出狀況時可用 `Enable-ScheduledTask` 隨時救回來。

---

## 過渡期注意事項

- **別讓兩台同時跑排程。** 兩台寫同一個 Google Drive 資料夾會產生「衝突副本」，而且會收到兩封重複的信。第 7 步完成前，新機只做手動測試，不要等排程自己觸發。
- 舊筆電上如果還要手動跑，先確認新機當天沒跑過。

## 事後檢查

跑幾天後回頭確認：

```powershell
Get-ScheduledTask | Where-Object { $_.TaskName -match 'ETF|法人' } | ForEach-Object {
  $i = $_ | Get-ScheduledTaskInfo
  "$($_.TaskName)  上次=$($i.LastRunTime)  結果=0x$('{0:X}' -f $i.LastTaskResult)"
}
```

`0x0` 才是成功。其他常見碼：

| 代碼 | 意義 |
|---|---|
| `0xC000013A` | 程序被強制終止（多半是達到 `ExecutionTimeLimit`） |
| `0x800710E0` | 要求被拒絕（電池條件不符，或錯過排程且未設補跑） |
| `0xFFFD0000` | 指令碼解析失敗（**通常是絕對路徑漏了「AI作品」這層**） |

也可直接看 log：`data\etf_holdings\logs\run-YYYY-MM-DD.log`、`data\institutional\logs\run-YYYY-MM-DD.log`。
